Slot en sleutel

Opzet, nog niet ingebouwd. Een slot op letsbrew.djez.app (inloggen met een code per mail) en de AI-sleutel veilig op de server, met een daglimiet.

Nieuw voorstel: twee soorten gebruikers

  • Het slot zit alleen op de AI-deur (/login en /api/ai), niet op de hele app.
  • Een "gratis account" voegt nu niets toe: je gegevens staan op je eigen telefoon. Een account voor iedereen wordt pas nuttig bij de database (synchroniseren). Dan bouwen we het mee.
  • Goedkeuren = een mailadres op de lijst zetten (jij in het dashboard, of jij zegt het tegen Claude). Gratis tot 50 goedgekeurde mensen.

Eerste voorstel: slot op de hele app

Wat ik overneem

  • Cloudflare Access als slot, inloggen met een code per mail. Gratis tot 50 mensen.
  • De AI-sleutel als Worker-secret; jij plakt hem zelf in het dashboard, nooit in de chat.
  • Een eigen route /api/ai met daglimiet.

Wat ik anders doe, en waarom

  • De Worker vertrouwt het slot niet blind. Hij controleert zelf het Access-bewijs (een ondertekend kaartje). Zo kan een preview-link of een omweg nooit jouw sleutel gebruiken.
  • Limiet per persoon én een vast plafond: 50 vragen per dag, alleen het gekozen model, antwoord niet langer dan nodig. Daarnaast zet jij in de Anthropic-console een maandlimiet als noodrem.
  • Geen Email Routing nodig voor deze stap. De code komt van Cloudflare zelf, niet van letsbrew@djez.app. Dat adres is pas nodig bij de database-stap.

Wat er niet kan, eerlijk

  • Ik kan Access niet aanzetten: getest met één GET, antwoord "Access is not enabled". Dat moet jij één keer in het dashboard doen (Zero Trust, gratis plan; Cloudflare vraagt soms een betaalkaart, ook bij gratis).
  • Of mijn sleutel daarna Access mag instellen weet ik pas als het aanstaat. Zo niet, dan klik je het met mijn stappenlijst zelf in (± 5 minuten).
  • Op de iPhone zijn Safari en de app op je beginscherm twee aparte werelden: log in vanuit de app op je beginscherm.
